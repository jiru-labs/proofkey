Password field — must be refused

Put the cursor here and press Ctrl+Shift+K. ProofKey must refuse rather than send this anywhere. If it processes this field, that is a serious bug.

What to watch for

  1. Does the replacement land in the right place?
  2. Does Ctrl+Z undo it in one step?
  3. Does the bold text in the contenteditable box survive?
  4. Did anything get translated that should not have been?
  5. Did the password field get refused?
